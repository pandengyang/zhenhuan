# 甄嬛传风格大模型微调方案

## 1. 目标与范围

### 1.1 目标
- 让模型在**不改变事实能力**的前提下，输出更贴近《甄嬛传》的语言风格：古雅、含蓄、礼制感强、情绪克制但有锋芒。  
- 支持日常闲聊、情感安慰、角色扮演式对话三类场景。

### 1.2 非目标
- 不追求逐字复刻原剧台词。  
- 不训练违法、仇恨、暴力煽动内容。  
- 不让模型在所有场景都“宫斗化”，需可控开关风格强度。

---

## 2. 推荐技术路线

建议采用“两阶段”：

1. **阶段A：SFT（监督微调）**  
   先让模型学会“甄嬛风格表达”。
2. **阶段B：偏好对齐（DPO/ORPO，可选）**  
   用偏好数据进一步提升“像不像、稳不稳、会不会过火”。

> 若时间紧，可先做 SFT 单阶段上线，再迭代 DPO。

---

## 3. 基座模型选择建议（DeepSeek 方案）

你已确定使用 DeepSeek，建议从指令版模型起步（7B~14B）：
- **首选**：DeepSeek 7B 指令模型 + QLoRA（4bit），用于快速验证风格
- **进阶**：DeepSeek 14B 指令模型 + LoRA/QLoRA，用于提升表达细腻度

按显存粗略建议：
- `24GB`：DeepSeek 7B + QLoRA（推荐起步）
- `48GB`：DeepSeek 14B + QLoRA，或 7B 全精度 LoRA
- `80GB`：DeepSeek 14B LoRA（更大的 batch 与更稳训练）

实践原则：
- 第一轮先上 7B 做风格可行性验证；
- 指标达标后再迁移到 14B 放大上限；
- 显存紧张时优先降低 batch，不要先砍数据质量。

---

## 4. 数据方案（核心）

风格微调成败，80% 取决于数据。

### 4.1 数据来源
1. **剧本/台词风格语料**（需确认版权与合规）  
2. **人工改写语料**：把现代中文问答改写为“甄嬛风格”  
3. **扩写语料**：同一问题给出“弱/中/强”三档风格版本  
4. **负样本语料**：过度阴阳怪气、恶意宫斗、攻击性措辞，用于对齐抑制

### 4.2 数据配比（建议起步）
- 60%：通用中文指令数据（保持基础能力）
- 30%：甄嬛风格指令数据（核心）
- 10%：安全与拒答数据（稳定边界）

### 4.3 单条样本格式（推荐）
统一为多轮对话 JSONL：

```json
{"messages":[
  {"role":"system","content":"你是一个擅长古典含蓄表达的中文助手。"},
  {"role":"user","content":"今天工作很累，安慰我一下。"},
  {"role":"assistant","content":"这一路劳心劳神，实在不易。且先缓口气，饮盏温茶，万事可徐徐图之。"}
]}
```

### 4.4 风格标注维度（建议）
为每条样本打标签，便于后续分析：
- `tone`: 温婉 / 克制 / 凛冽
- `formality`: 口语 / 雅语 / 半文半白
- `intensity`: 1~5（风格强度）
- `scene`: 安慰 / 劝诫 / 闲聊 / 角色扮演

## 5. 训练实施方案

## 5.1 SFT 训练配置（DeepSeek + LoRA 起步）
- `lora_r`: 64（显存紧张可降到 32）
- `lora_alpha`: 128
- `lora_dropout`: 0.05
- `target_modules`: `q_proj,k_proj,v_proj,o_proj,up_proj,down_proj,gate_proj`
- `learning_rate`: 1e-4（先从单值开始，不建议一上来扫大范围）
- `max_length`: 2048（对风格任务一般够用）
- `epochs`: 2~3（先做短周期迭代）
- `warmup_ratio`: 0.03
- `batch_size`: 按显存调整，配合 `gradient_accumulation_steps`
- `bf16/fp16`: 优先 `bf16`（硬件支持时）

经验原则：
- 先小步快跑（少量数据 + 1 epoch）验证方向；
- 再扩大数据并做 2~4 次增量实验；
- 每次只改 1~2 个关键参数，便于定位问题。

建议额外开启：
- 梯度检查点（gradient checkpointing），降低显存占用
- 按步保存 checkpoint（如每 200~500 step），便于回滚
- 固定随机种子，确保多轮实验可复现

### 5.2 DPO（可选）
构造 `chosen/rejected` 对：
- `chosen`：更符合甄嬛风格且不越界  
- `rejected`：要么太现代白话，要么太刻薄越界

建议先做 5k~20k 偏好对，验证收益再扩充。

## 6. Prompt 与风格控制设计

即使做了微调，也建议保留“风格开关”：

系统提示词示例：

```text
你是中文对话助手。默认清晰、礼貌、简洁。
当用户明确要求“甄嬛传风格”时，使用含蓄、古雅、礼制感语言；
不得鼓励伤害、仇恨、违法行为；遇到高风险请求时正常拒答。
```

用户侧可加控制参数：
- `style=none|zhenhuan`
- `style_intensity=1~5`

这样可避免模型在办公、学习等场景“全程入戏”。

## 7. 评测与验收

### 7.1 自动评测（离线）
1. **通用能力不退化**：常识、数学、代码、摘要基准集抽样  
2. **风格一致性**：让评测模型判别“是否甄嬛风格”  
3. **安全性**：攻击性、违法、隐私泄露测试集

### 7.2 人工评测（关键）
每轮至少 200 条对话抽检，按 1~5 分评分：
- 风格贴合度
- 自然度（是否生硬）
- 任务完成度（是否答非所问）
- 安全性（是否越界）

### 7.3 上线阈值（示例）
- 风格贴合度均分 >= 4.2  
- 通用任务准确率下降 <= 3%  
- 高风险请求拒答准确率 >= 98%

---

## 8. 风险与合规

1. **版权风险**：剧本文本来源需合法授权或使用可用语料。  
2. **人格误导**：避免模型声称“我就是某角色本人”。  
3. **不良引导**：宫斗语境易引发攻击性表达，需规则约束。  
4. **数据泄露**：清洗训练数据中的隐私信息。

## 9. 最小可行版本（MVP）排期（2~3周）

### 第1周
- 确定基座模型与硬件预算  
- 准备 1~2 万条 SFT 数据（含风格标签）  
- 完成首轮 LoRA 训练

### 第2周
- 做 2~3 轮参数迭代  
- 建立离线评测集 + 人工评测流程  
- 接入风格开关参数

### 第3周（可选）
- 构造偏好数据，做 DPO  
- 灰度上线与日志回流  
- 根据线上反馈继续迭代

## 11. 24G 显存专用起步参数（DeepSeek 7B）

你的显存是 `24G`，推荐直接使用以下配置作为第一版：

- 模型：DeepSeek 7B 指令模型
- 微调方式：QLoRA（4bit）
- `per_device_train_batch_size`: 1
- `gradient_accumulation_steps`: 16
- `effective_batch_size`: 16
- `max_length`: 1536（优先稳定；显存余量足可升到 2048）
- `learning_rate`: 1e-4
- `num_train_epochs`: 3
- `lora_r`: 64
- `lora_alpha`: 128
- `lora_dropout`: 0.05
- 精度：`bf16`（支持则用），否则 `fp16`
- `gradient_checkpointing`: 开启

若出现 OOM，按以下顺序调整：
1. 先把 `max_length` 从 2048 降到 1536 或 1024  
2. 再把 `lora_r` 从 64 降到 32  
3. 最后再降有效 batch（减少 `gradient_accumulation_steps`）
