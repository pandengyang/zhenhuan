# 微调 DeepSeek 实战方案（学习版）

这份方案目标是：**用最低门槛跑通一次微调流程**，并理解每一步在做什么。  
建议先完成“最小可跑通方案”，再做进阶优化。

---

## 1. 学习目标（先明确你要学什么）

第一阶段建议只追求 3 件事：
- 能成功训练并导出一个 LoRA 适配器；
- 能对比“微调前 vs 微调后”的输出差异；
- 能解释数据、参数、评估三者的关系。

---

## 2. 技术路线选择（适合新手）

推荐路线：**QLoRA + 指令微调（SFT）**

为什么这样选：
- 显存需求低（消费级 GPU 也能练习）；
- 训练成本可控，出结果快；
- 资料成熟，容易排错。

建议模型（任选其一）：
- `deepseek-ai/deepseek-llm-1.3b-base`（轻量，适合入门练习）
- `deepseek-ai/deepseek-llm-7b-base`（效果更好，资源要求更高）

如果你是代码任务（代码生成/修复），可优先尝试 DeepSeek-Coder 系列。

---

## 3. 环境准备

## 3.1 硬件建议
- 最低：单卡 8GB 显存（可跑非常小 batch）
- 推荐：12GB~24GB 显存（训练更稳定）

## 3.2 软件环境
- Python 3.10+
- CUDA 对应版本（NVIDIA）
- 核心库：`transformers`、`datasets`、`peft`、`trl`、`accelerate`、`bitsandbytes`

安装示例：

```bash
pip install -U transformers datasets peft trl accelerate bitsandbytes sentencepiece
```

---

## 4. 数据准备（决定上限）

学习阶段推荐做一个小型指令数据集（200~2000 条）：
- 每条包含：`instruction`、`input`（可空）、`output`
- 尽量保证“任务单一、格式统一、答案高质量”

示例格式（JSON）：

```json
{
  "instruction": "将下面句子改写为正式商务语气",
  "input": "这个功能下周给你",
  "output": "该功能预计将于下周交付。"
}
```

数据原则：
- 宁可少而精，不要多而乱；
- 去重、去错别字、去冲突标注；
- 先做一个小而干净的数据集验证流程。

---

## 5. 训练流程（最小可跑通）

1) 选择基础模型（如 `deepseek-ai/deepseek-llm-1.3b-base`）  
2) 加载 4bit 量化模型（QLoRA）  
3) 配置 LoRA 参数（如 `r=8/16`）  
4) 用 SFTTrainer 训练 1~3 个 epoch  
5) 保存 LoRA adapter  
6) 用同一组测试问题做前后对比

关键训练参数建议（学习版）：
- `learning_rate`: `2e-4`
- `num_train_epochs`: `1~3`
- `per_device_train_batch_size`: `1~4`（按显存调）
- `gradient_accumulation_steps`: `4~16`
- `max_seq_length`: `512` 或 `1024`
- `lora_r`: `8`（显存紧张）或 `16`（效果更稳）

---

## 6. 评估方案（不要只看 loss）

至少做两类评估：

1) **离线样例评估（必做）**
- 固定 20~50 条测试指令；
- 对比微调前后输出；
- 人工打分：正确性、格式遵循、稳定性。

2) **简单自动评估（选做）**
- BLEU/ROUGE（文本任务）
- 分类准确率（分类任务）

重点看：
- 是否更符合你定义的输出风格；
- 是否出现过拟合（训练集好、测试集差）；
- 是否出现灾难性遗忘（通用能力下降明显）。

---

## 7. 一周学习节奏（可直接照做）

Day 1：
- 搭好环境，下载模型，跑通推理。

Day 2：
- 准备 200~500 条高质量数据，完成清洗与格式化。

Day 3：
- 首次 QLoRA 训练（小 epoch），导出 adapter。

Day 4：
- 做前后对比评估，记录问题（答非所问、格式漂移等）。

Day 5：
- 调参（学习率、epoch、LoRA r），进行第二轮训练。

Day 6：
- 扩数据到 1000+ 条，复训并评估泛化。

Day 7：
- 总结实验表（数据规模、参数、指标、结论），形成你的微调方法论。

---

## 8. 常见坑与规避

- 数据质量差：模型学到噪声，效果不稳定。  
- 训练轮数过高：容易“背答案”，泛化下降。  
- 只看 loss：业务表现未必提升。  
- 指令模板不一致：模型输出格式漂移。  
- 显存不足硬顶：先减序列长度、batch、LoRA rank。

---

## 9. 进阶方向（跑通后再做）

- 尝试 DPO/ORPO 做偏好对齐；
- 进行多任务混合微调（分类+改写+问答）；
- 引入 RAG，对比“仅微调”和“RAG+微调”；
- 做量化部署（4bit/8bit）与推理加速。
